# SAST 对比 DAST 对比 RASP：应用安全测试方法比较

学习 2024 年 12 月 18 日 Shanika Wickramasinghe

到 2025 年，全球信息安全支出预计将达到 2120 亿美元，这比 2024 年增长了 15%。据 Gartner 称，生成式 AI 的兴起和云采用是这一快速增长的关键原因。该分析机构进一步预测，到 2027 年，GenAI 将在所有网络攻击中扮演 17% 的角色。

企业需要超越传统方法的先进安全策略，以应对这些日益增长的威胁。这就是为什么企业所有者需要了解 SAST、DAST 和 RASP 等安全解决方案，因为它们为应用提供了多层防护。

（相关阅读：应用安全详解 & 常见软件测试方法。）

## 什么是 SAST？

静态应用安全测试（SAST）是一种白盒安全测试方法。SAST 使用应用的静态源代码或二进制文件来识别漏洞。这意味着 SAST 工具在应用未运行时对其代码进行操作。

开发者使用 SAST 来检测各种安全风险，例如：跨站脚本（XSS）、不安全的反序列化、缓冲区溢出，以及代码中的其他 OWASP 漏洞。由于仅凭 SAST 无法识别特定于运行时的漏洞，开发者通常必须将 SAST 与其他测试方法结合使用，以实现全面的安全性。

SAST 是软件开发生命周期的重要组成部分，因为它能在早期检测到漏洞。越早发现漏洞，修复它们的成本就越低。由于 SAST 工具可以在开发阶段执行，开发者现在能够在将产品推向市场之前编写代码并测试上千次（!!）。

SAST 可以集成到 CI/CD 流水线中，当这样做时，它被称为“安全 DevOps”或“DevSecOps”。SAST 通过自动化具有广泛的可扩展性。能够实现涵盖 SAST 技术的自动化测试，使其成为快速解决代码级风险的高效解决方案。

## 什么是 DAST？

动态应用安全测试（DAST）是一种黑盒测试方法。DAST 中的“动态（Dynamic）”一词表明，该方法在应用运行时评估其安全性。与 SAST 不同，DAST 不需要访问应用的源代码。相反，它：

- 模拟外部攻击者的行为。

- 从外部测试应用，以识别仅在运行时才出现的漏洞。

DAST 有能力识别各种安全缺陷，如拒绝服务（DoS）漏洞和不安全的服务器配置。通过模拟真实世界的攻击场景，DAST 工具评估应用对这些模拟威胁的响应方式。通过这种方法，开发者可以识别出像 SAST 这样的静态测试方法可能遗漏的弱点。

通常，开发者在软件开发生命周期的后期阶段执行 DAST，往往就在部署之前。通过在实际环境中测试应用，DAST 提供了运行时安全性的清晰概览，并支持性能更好、能够抵御潜在攻击的应用。

## SAST 如何工作？

开发者使用 SAST 工具来应用预定义规则和其他检测方法——例如模式匹配和数据流分析——来识别编码错误和其他漏洞。他们将这些工具集成到 IDE 或 CI/CD 流水线中，以在编码和测试阶段实现自动化扫描。

### 常见的 SAST 方法

以下是 SAST 中使用的一些方法。

[图: Common Static Aplication Security Testing methods]

模式匹配扫描代码库，寻找已知的不安全编码实践模式。例如，使用弱加密算法或不安全的 API 调用。

数据流（Data flow）追踪数据如何流经应用。通过追踪不可信输入路径到敏感操作，这可以识别 SQL 注入或缓冲区溢出等漏洞。

控制流分析可以分析应用的控制结构。例如，循环和条件语句，以发现逻辑缺陷或竞态条件等潜在漏洞。

自定义规则创建。许多工具允许开发者创建自定义规则以遵循编码最佳实践。以下是这些自定义规则的一些示例：

- 标记 SQL 查询中对未消毒（未净化）输入的任何使用。

- 识别未进行适当转义就将用户提供的数据输出到浏览器的代码。

- 高亮使用易受攻击或已弃用的函数，例如 JavaScript 中的 `eval()` 或 C 中的 `strcpy()`。

- 检测源代码中硬编码的 API 密钥和密码的出现，并标记任何对用户提供的数据缺少输入验证的实例。

依赖扫描。一些 SAST 工具分析应用中使用的第三方库和框架，以识别依赖中的漏洞。

语义分析。通过解读代码的含义而不仅仅是其结构，SAST 工具可以检测不安全的配置或 API 的误用。

机器学习模型：先进的 SAST 工具结合机器学习算法，通过分析大型数据集中的模式来识别以前未知的漏洞。

### 使用 SAST 工具时的性能考量

SAST 工具通常需要大量的 CPU 和内存资源。在分析大型代码库时，这可能是一个主要问题。对一百万行代码的完整扫描可能会消耗数 GB 的 RAM。

SAST 扫描所需的时间可能根据代码库的大小而差异巨大，从小型项目的几分钟到企业级应用的数小时不等。这可能会影响：

- 构建流水线的时间线

- 开发者生产力

考虑使用支持增量扫描的现代 SAST 工具，这样你可以只分析更改过的代码，而不是整个代码库。

此外，通过规则选择和范围定义进行性能调优至关重要。配置不当的 SAST 工具可能会不必要地分析非关键代码路径，浪费时间和资源而无法提供安全收益。

## DAST 如何工作？

DAST 工具模拟真实世界的攻击——例如，向输入字段发送各种形式的恶意数据，以查看应用如何处理这些数据——以识别应用行为和响应中的漏洞和弱点。

### DAST 的步骤

该过程通常包括以下步骤。

[图: Dynamic Application Security Testing Steps]

步骤 1：扫描。扫描 Web 应用以发现入口点（例如 URL、表单和 API）。此步骤绘制出应用的结构并识别潜在的攻击面。

步骤 2：攻击模拟。通过向应用发送精心构造的请求来模拟恶意活动。这些请求试图利用入口点来测试跨站脚本和跨站请求伪造等漏洞。

步骤 3：漏洞检测。分析应用的响应以识别安全弱点。它评估应用在攻击下是否按预期行为。例如，可以注入恶意数据来检测 SQL 注入缺陷。

步骤 4：报告。生成带有已检测漏洞和修复建议的报告。开发者可以使用报告中的结果来修复已识别的问题。

现代 DAST 解决方案可以整合先进功能，例如 AI 驱动的分析和实时数据集成。它们自动创建测试集，动态地适应应用的结构，并使用机器学习算法将误报降至最低。

### 使用 DAST 工具时的性能考量

以下是使用 DAST 工具时需要注意的某些性能瓶颈。

- DAST 工具与运行中的应用主动交互，会暂时增加应用服务器和 Web 服务器的 CPU 和内存使用。

- DAST 扫描期间产生的大量并发请求可能会消耗大量网络带宽。

- DAST 扫描器通常通过生成独特请求来绕过或使应用缓存失效，从而降低缓存机制的有效性。

- DAST 工具创建和管理多个测试会话可能会增加应用服务器的内存使用。

为避免此类问题或尽可能减少其影响，请遵循以下做法。

- 在应用使用量最低的非高峰时段安排 DAST 扫描。

- 在与生产设置相同的预发布或预生产环境中进行扫描。

- 使用 DAST 工具中的节流功能来控制同时请求的数量。

- 在扫描期间增加应用服务器的线程池。

- 为 DAST 扫描器的 IP 配置单独的缓存策略。

- 如果超出性能阈值，则实施自动扫描暂停。

## SAST 和 DAST 的优缺点

### SAST 的优点

- 在软件开发生命周期的早期识别安全漏洞。

- 分析代码库，包括基本函数和复杂分支。

- 直接对源代码进行操作，无需应用运行。

- 提供实时反馈和全面的洞察，例如漏洞的确切位置。

- 生成可使用仪表盘跟踪的可导出报告。

- 支持自动化，因此比手动代码评审更快、更高效。

### SAST 的缺点

- 通常会产生大量误报。因此，可能需要手动评审。

- 无法识别运行时或环境特定的漏洞，例如配置错误。

- 需要针对每种编程语言的特定工具，因此维护复杂。

- 难以理解外部库、API 和 REST 端点。

### DAST 的优点

- 识别仅在应用执行期间才出现的漏洞。

- 从外部操作，无需访问源代码。这对于测试第三方应用或已编译的代码很有效。

- 模拟实际攻击场景，识别 SAST 遗漏的风险。

- 独立于应用的编程语言工作。

- 评估整个应用和系统。这包括内存消耗、资源使用和第三方接口。

### DAST 的缺点

- 只关注应用的外层，可能会遗漏更深层的漏洞。

- 在 SDLC 中应用较晚，因此修复成本更高、更耗时。

- 会遗漏 SAST 工具可以通过源代码分析识别的某些漏洞。例如，考虑一个使用不安全随机数生成器（如 JavaScript 中的 `Math.random()`）来创建会话令牌的 Web 应用。DAST 可能会遗漏这一缺陷，因为它只测试运行时行为。（但 SAST 可以检测到它。）

- 大型项目需要自定义基础设施以及应用的多个实例并行运行，因此资源密集。

## 我应该在什么时候使用 SAST 对比 DAST？

SAST 和 DAST 在保障 SDLC 安全方面发挥着互补作用。了解何时使用每一种，有助于获得全面的安全覆盖。

### 何时使用 SAST

在早期开发阶段。开发者使用 SAST 在 SDLC 早期识别 SQL 注入和硬编码凭据等漏洞。通过在部署前捕获这些问题，他们降低了修复的成本和复杂性。

例如：- SAST 工具扫描 Python 代码，并标记出源代码中嵌入了硬编码 API 密钥的漏洞。开发者重构代码，使用环境变量来安全地存储和检索这些密钥。

用于代码评审。SAST 集成到版本控制系统中，允许开发者在提交代码之前对其进行扫描。这确保了只有安全的代码进入仓库。

示例：SAST 工具可以检测到一种漏洞：文件路径直接由未经验证的用户输入构造而成，从而使应用暴露于路径遍历攻击。开发者通过消毒输入并使用安全库函数处理文件路径来修复该问题。

在持续集成/持续部署流水线中。SAST 在 CI/CD 过程中运行自动化扫描，为开发者提供实时反馈。

### 何时使用 DAST

预生产测试。开发者使用 DAST 在预发布或 QA 环境中识别运行时漏洞（例如：不安全的配置、身份认证缺陷、访问控制不足）。

示例：DAST 工具可以检测到暴露敏感数据的数据库错误配置。然后开发者可以在部署前确保配置安全。

在部署后监控中。DAST 工具持续扫描已部署的应用，以发现由环境变化或新出现的威胁引起的漏洞。这保证了应用随着时间的推移始终保持安全。

测试第三方集成。DAST 可以模拟外部攻击者的视角，以识别第三方 API 或互连系统中的漏洞。

例如：DAST 工具测试一个 Web 应用，并在第三方支付 API 中发现一个漏洞：信用卡详细信息通过未加密的 HTTP 连接传输。开发者通过为所有 API 通信强制使用 HTTPS 来解决该问题。

## 哪个更有效：SAST 还是 DAST？

SAST 或 DAST 的有效性取决于：

- SDLC 阶段

- 正在处理的漏洞类型

SAST 在早期开发中效果最好，主要用于识别源代码中的漏洞、降低成本并推广安全编码实践。相比之下，DAST 专注于预生产或已部署应用中的运行时漏洞，提供对错误配置和不安全集成等问题的洞察。

### 采用混合方法

与其在两者之间选择其一，不如将 SAST 和 DAST 结合起来，创建一个多层安全策略，同时解决静态代码和运行时环境中的漏洞。SAST 可以集成到早期开发阶段，在应用编译之前检测并修复代码级问题。一旦应用在测试环境中运行，DAST 就可以识别运行时漏洞，并评估应用在攻击条件下的行为。

在 CI/CD 流水线中自动化 SAST 和 DAST 扫描，可以在不牺牲安全性的情况下提供持续反馈并加速开发过程。

对于敏捷或 DevOps 环境，添加 IAST 或 RASP 等工具可以进一步增强安全性。通过关联 SAST 和 DAST 的结果，组织可以实现更全面、更有效的漏洞管理。

### 使用 RASP 作为 SAST 和 DAST 的替代方案

运行时应用自我保护（RASP）是一种先进的安全解决方案，直接安装在应用运行的服务器上。

RASP 将自身嵌入到应用的运行时环境中。这种集成使 RASP 能够分析应用的逻辑和数据。在分析时，它可以：

- 在异常行为发生时检测它们。

- 立即阻止恶意活动。

一个关键区别在于，RASP 不仅仅是针对潜在问题发出警报——它还通过隔离和解决威胁来主动阻止攻击，而无需依赖外部工具。

RASP 提供了 SAST 和 DAST 之外的动态替代方案。与分析静态代码的 SAST 和模拟外部攻击的 DAST 不同，RASP 实时运行。它监控应用在执行期间的行为，并通过终止会话或向防御者发出警报来响应实时威胁。

RASP 在保护应用免受绕过网络防御或在开发期间被遗漏的漏洞方面特别有效。

然而，对 RASP（运行时应用自我保护）的过度自信可能导致组织忽视安全编码实践。此外，RASP 可能会影响应用性能，因为它直接运行在应用的运行时环境中。RASP 无法取代修复底层缺陷的必要性，但在修复进行期间，它能提供持续的保护。

正如一位 RASP 用户评论道：

“是否使用 RASP 工具，应基于对应用特定需求与风险状况的全面评估。”

## 未来是结合 SAST、DAST 和 RASP 的应用安全（AppSec）测试

应用测试的未来在于结合 SAST、DAST 和 RASP，构建全面的安全策略。随着安全挑战日益加剧，将这些工具集成到 CI/CD 流水线中并实现流程自动化，将变得至关重要。

AI 和机器学习方面的进展将使测试更加高效，因为它有助于减少误报并改进威胁检测。

### 金融与金融服务（FinServ）行业

在金融行业，AI 驱动的工具将改变漏洞的检测与缓解方式。SAST 和 DAST 将继续在开发阶段和预生产阶段识别编码缺陷与运行时问题。

但这还不够：RASP 将更进一步，利用 AI 监控实时交易。例如，RASP 可以检测到异常模式（例如：攻击者试图实时利用某个漏洞），并在通知安全团队的同时阻止这些活动。

### 物联网（IoT）、边缘与互联设备

就物联网而言，这些工具的组合将在保护互联设备方面发挥重要作用。具体方式如下：

- SAST 可以在开发阶段确认固件不存在漏洞。

- DAST 可以测试设备之间通信协议的安全性。

- 与此同时，RASP 会监控已部署的设备，检测并阻止由新出现的威胁所导致的未授权访问企图或数据泄露。

同样地，使用多种方法将有助于物联网生态系统保持韧性。正如我们在诸多示例中所阐述的，SAST、DAST 与 RASP 三者协同，预示着这样一个未来：应用将以更强大、更主动的安全措施来构建和部署。

## 韧性安全始于主动测试

将 SAST、DAST 和 RASP 结合使用，可以提供覆盖整个软件开发生命周期的稳健安全防护。

通过将这些方法集成到 CI/CD 流水线中，并利用 AI 方面的进展，组织能够主动应对不断出现的威胁。这些方法共同提供了一种整体性的方法，用于保护现代应用免受安全漏洞的侵害。
