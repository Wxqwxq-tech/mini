# 介绍 MCP 注册表

以预览版推出 MCP 注册表：一个用于发现公开可用 MCP 服务器的开放目录与接口（API）。

2025 年 9 月 8 日 · 4 分钟 · David Soria Parra（首席维护者）、Adam Jones（注册表维护者）、Tadas Antanavicius（注册表维护者）、Toby Padilla（注册表维护者）、Theodora Chu（Anthropic 的 MCP 产品经理）

今天，我们推出了模型上下文协议（MCP）注册表——一个面向公开可用 MCP 服务器的开放目录与接口（API），旨在改善可发现性与实现体验。通过标准化服务器的分发与发现方式，我们在扩大其覆盖范围的同时，也让客户端更容易接入。

MCP 注册表现已以预览版提供。开始使用：

- 按照我们的《向 MCP 注册表添加服务器》指南添加你的服务器（面向服务器维护者）

- 按照我们的《访问 MCP 注册表数据》指南访问服务器数据（面向客户端维护者）

# MCP 服务器的唯一事实来源#

2025 年 3 月，我们曾表示希望为 MCP 生态系统构建一个中心化注册表。今天，我们宣布已上线 https://registry.modelcontextprotocol.io，作为官方的 MCP 注册表。作为 MCP 项目的一部分，MCP 注册表及其父级 OpenAPI 规格都是开源的——任何人都可以据此构建兼容的子注册表。

我们的目标是标准化服务器的分发与发现方式，提供一个子注册表可以构建于其上的主要事实来源。反过来，这将扩大服务器的覆盖范围，并帮助客户端在整个 MCP 生态系统中更轻松地找到服务器。

## 公开与私有子注册表#

在构建中心化注册表时，对我们来说重要的是不要剥夺社区和公司已经建立起来的现有注册表。MCP 注册表充当公开可用 MCP 服务器的主要事实来源，组织可以选择基于自定义标准创建子注册表。例如：

与每个 MCP 客户端相关的、带有主观取向（opinionated）的“MCP 市场”之类的公开子注册表，可以自由地扩充和增强它们从上游 MCP 注册表摄取的数据。每个 MCP 最终用户角色都有不同的需求，如何以带有主观取向的方式妥善服务其最终用户，取决于各个 MCP 客户端市场。

私有子注册表将存在于对隐私和安全有严格要求的组织内部，但 MCP 注册表为这些企业提供了一个可供其构建于其上的单一上游数据源。至少，我们旨在与这些私有实现共享接口（API）模式，以便相关的软件开发工具包（SDK）和工具能够在整个生态系统中共享。

在这两种情况下，MCP 注册表都是起点——它是一个中心化场所，MCP 服务器维护者在此发布和维护其自报的信息，供这些下游使用者加工后交付给其最终用户。

## 由社区驱动的审核机制#

MCP 注册表是一个由注册表工作组维护、并采用宽松许可证授权的官方 MCP 项目。社区成员可以提交 Issue 来标记违反 MCP 审核准则的服务器——例如包含垃圾信息、恶意代码或冒充合法服务的服务器。注册表维护者随后可以将这些条目加入黑名单，并追溯性地将其从公开访问中移除。

# 开始使用#

开始使用：

- 按照我们的《向 MCP 注册表添加服务器》指南添加你的服务器（面向服务器维护者）

- 按照我们的《访问 MCP 注册表数据》指南访问服务器数据（面向客户端维护者）

MCP 注册表的这一预览版旨在帮助我们在正式发布（GA）之前改进用户体验，且不提供数据持久性保证或其他担保。我们建议 MCP 采用者密切关注开发进展，因为在注册表正式发布之前可能会发生破坏性变更。

随着我们继续开发该注册表，我们鼓励大家在 modelcontextprotocol/registry 这个 GitHub 仓库上提供反馈和贡献：讨论（Discussion）、Issue 以及拉取请求（PR）都欢迎。

# 感谢 MCP 社区#

MCP 注册表从一开始就是一项协作成果，我们对广大开发者社区的热情与支持深表感激。

2025 年 2 月，当 MCP 的创建者 David Soria Parra 和 Justin Spahr-Summers 邀请 PulseMCP 与 Goose 团队帮助构建一个中心化社区注册表时，它作为一个基层项目起步。来自 PulseMCP 的注册表维护者 Tadas Antanavicius 与来自 Block 的 Alex Hancock 合作，率先发起了最初的工作。很快，GitHub 的 MCP 负责人、注册表维护者 Toby Padilla 加入了他们，再后来，来自 Anthropic 的 Adam Jones 以注册表维护者身份加入，推动项目走向今天的发布。关于 MCP 注册表开发的最初公告列出了来自至少 9 家不同公司的 16 位贡献者。

许多其他人也为这个项目的诞生做出了重要贡献：来自 Stacklok 的 Radoslav Dimitrov、来自 GitHub 的 Avinash Sridhar、来自 VS Code 的 Connor Peet、来自 NuGet 的 Joel Verhagen、来自 Last9 的 Preeti Dewani、来自 Microsoft 的 Avish Porwal、Jonathan Hefner，以及众多提供代码评审和开发支持的 Anthropic 和 GitHub 员工。我们同样感谢注册表贡献者名单上的每一个人，以及参与讨论和 Issue 的所有人。

我们深深感谢每一位投入这项基础性开源基础设施的人。我们一起帮助世界各地的开发者和组织构建更可靠、更具上下文感知（context-aware）能力的 AI 应用。谨代表 MCP 社区，向大家致谢。
