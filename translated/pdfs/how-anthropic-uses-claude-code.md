基础设施的 Claude Code
数据基础设施团队
为公司内所有团队组织全部业务数据。他们使用 Claude Code 来自动化日常的数据工程任务、排查复杂的基础设施问题，并为技术和非技术团队成员创建文档化的工作流，使其能够独立访问和操作数据。
Claude Code 的主要用例
借助截图进行 Kubernetes 调试
当 Kubernetes 集群宕机、不再调度新的 Pod 时，团队使用 Claude Code 来诊断问题。他们将仪表盘的截图输入 Claude Code，后者一步步引导他们浏览 Google Cloud 的用户界面（UI），直到找到一条警告，表明 Pod IP 地址已经耗尽。随后 Claude Code 提供了精确的命令，用于创建新的 IP 池并将其添加到集群中，从而免去了引入网络专家的需要。
为财务团队准备的纯文本工作流
团队向财务团队成员展示了如何编写描述其数据工作流的纯文本文件，然后将其载入 Claude Code 以获得全自动的执行。没有任何编程经验的员工也能描述诸如“查询这个仪表盘、获取信息、运行这些查询、生成 Excel 输出”这样的步骤，而 Claude Code 会执行整个工作流，包括询问日期之类的必需输入。
面向新员工的代码库导航
当新的数据科学家加入团队时，他们会被引导使用 Claude Code 来浏览庞大的代码库。Claude Code 会读取他们的 Claude.md 文件（文档）、识别与特定任务相关的文件、解释数据管线之间的依赖关系，并帮助新成员理解哪些上游数据源会流入仪表盘。这取代了传统的数据目录和可发现性工具。
会话结束时的文档更新
团队会让 Claude Code 在每项任务结束时总结已完成的工作会话并提出改进建议。这形成了一个持续改进的循环：Claude Code 根据实际使用情况帮助完善 Claude.md 文档和工作流说明，从而使后续的迭代更加高效。
跨多个实例的并行任务管理
在处理长时间运行的数据任务时，他们会在不同仓库中为不同项目打开多个 Claude Code 实例。每个实例都保持完整的上下文，因此当他们在数小时或数天后切回时，Claude Code 依然记得他们此前在做什么、进行到了哪一步，从而实现了真正并行的工作流管理，且不会丢失上下文。

用于产品
开发的 Claude Code
Claude Code 团队使用他们自己的产品来构建 Claude Code 的更新，从而扩展该产品的企业级能力和智能体式循环功能。
Claude Code 的主要用例
借助自动接受（auto-accept）模式快速原型开发
工程师们通过启用“自动接受模式”（shift+tab）并搭建自主循环，让 Claude 编写代码、运行测试并持续迭代，从而用 Claude Code 进行快速原型开发。他们把不熟悉的抽象问题交给 Claude，让其自主工作，然后在接手做最终打磨之前先评审那 80% 已完成的解决方案。各团队强调从一个干净的 git 状态开始，并定期提交检查点（checkpoint），这样一旦 Claude 跑偏，就能轻松回退任何错误的改动。
为核心功能进行同步编码
对于涉及应用业务逻辑的更关键的功能，团队会与 Claude Code 同步工作，给出带有具体实现说明的详尽提示。他们实时监控过程，以确保代码质量、符合风格指南以及架构合理，同时让 Claude 处理重复性的编码工作。
构建 Vim 模式
他们最成功的异步（async）项目之一是为 Claude Code 实现 Vim 按键绑定。他们请 Claude 构建整个功能（尽管这并非优先事项），最终实现中大约 70% 来自 Claude 的自主工作，只需几次迭代即可完成。
生成测试与修复缺陷
他们使用 Claude Code 在实现功能后编写全面的测试，并处理在拉取请求（PR）评审中发现的简单缺陷修复。他们还利用 GitHub Actions 集成，让 Claude 自动处理诸如格式问题或函数重命名之类的拉取请求（PR）评论。
代码库探索
在处理不熟悉的代码库时（例如 monorepo 或 API 一侧），团队使用 Claude Code 来快速理解系统是如何运作的。与其等待 Slack 的回复，他们直接向 Claude 询问解释和代码引用，从而在上下文切换上节省了大量时间。

安全工程团队专注于保障 
软件开发生命周期、供应链安全 
以及开发环境安全。

Claude Code 的主要用例
复杂基础设施调试 
在处理事故时，他们向 Claude Code 提供堆栈跟踪（stack trace）和 
文档，要求它追踪代码库中的控制流。这 
显著缩短了生产问题的解决时间，让他们能在大约 
5 分钟内理解通常需要 10-15 分钟手动扫描代码才能搞清的问题。
Terraform 代码评审与分析 
对于需要安全审批的基础设施变更，他们将 Terraform 
计划复制到 Claude Code 中，询问「这会做什么？我 
会后悔吗？」这形成了更紧密的反馈循环，使 
安全团队能够更快地评审和批准基础设施 
变更，减少开发流程中的瓶颈。
文档综合与运行手册（runbook） 
他们让 Claude Code 摄取多个文档来源，并 
生成 markdown 格式的运行手册（runbook）、故障排查指南和概览。 
他们将这类精简文档作为调试真实 
问题的上下文，形成比搜索完整 
知识库更高效的工作流。
测试驱动开发工作流 
取代过去「设计文档 → 粗糙代码 → 重构 → 放弃 
测试」的模式，他们现在先向 Claude Code 索取伪代码，引导 
它进行测试驱动开发，并在卡住时定期检查以纠正 
方向，从而产出更可靠、更可测试的代码。
上下文切换与项目上手 
在为诸如「dependant」（一个用于安全审批工作流的 Web 
应用）等现有项目做贡献时，他们使用 Claude Code 
编写、评审和执行以 markdown 编写并 
存储在代码库中的规格说明，从而在几天而非 
几周内做出有意义的贡献。

构建 JavaScript/TypeScript 仪表盘应用

创建持久化的分析工具，而不是一次性笔记本（notebook）

团队不再构建会被丢弃的一次性 Jupyter notebook，而是让 Claude 构建可跨未来模型评估复用的永久性 React 仪表盘。这一点很重要，因为理解 Claude 的性能是“团队最重要的事情之一”——他们需要理解模型在训练和评估期间的表现，而这“实际上并非易事，简单的工具仅凭看一个数字上涨，无法获得太多信号”。

零依赖的任务委派

Claude Code 成为主要的设计工具，80% 的时间里 Figma 和 Claude Code 都处于打开状态。

执行速度提升 2-3 倍

以往需要与工程师反复来回沟通的视觉和状态管理改动，现在可以直接实现。

周期从数周缩短到数小时

诸如 GA（正式发布）发布文案这类复杂项目，过去需要一周的协调，现在只需两次 30 分钟的通话即可完成。

两种截然不同的用户体验

开发人员获得“增强型工作流”（更快的执行速度），而非技术用户则获得“天哪，我成开发人员了”式的工作流（获得了以前完全不可能拥有的全新能力）。

设计与工程协作得到改善

由于设计人员事先就了解系统的约束和可能性，沟通更顺畅，解决问题也更快。

请工程师帮忙做好初始配置

让工程团队的同事协助完成初始的仓库配置和权限设置——对非开发人员而言，技术上手颇具挑战，但一旦配置完成，它就会彻底改变日常工作流。

使用自定义记忆文件来引导 Claude 的行为

创建具体的说明，告诉 Claude 你是一名几乎没有编码经验的设计人员，需要详细的解释和更小、更渐进式的改动，这能显著提升 Claude 回复的质量，让它不那么令人望而生畏。

借助粘贴图片进行原型设计

使用 Command+V 将截图直接粘贴到 Claude Code 中——它在读取设计稿和生成可用代码方面表现出色，对于将静态设计稿转化为工程师可以立即理解并继续开发的交互式原型来说，这一功能价值非凡。

Claude Code 用于强化学习（RL）工程
强化学习（RL）工程团队专注于强化学习中的高效采样（sampling）以及跨集群的权重传输（weight transfer）。他们主要使用 Claude Code 来编写中小型功能、调试，以及理解复杂的代码库，采用一种包含频繁检查点（checkpoint）与回滚（rollback）的迭代式方法。
Claude Code 的主要用例
有监督自主性（supervised autonomy）下的功能开发
团队让 Claude Code 为中小型功能编写大部分代码，同时进行监督（oversight），例如为权重传输组件实现身份认证（authentication）机制。他们以交互方式工作，让 Claude 主导，但在其偏离方向时加以引导。
测试生成与代码评审
在自己完成变更实现之后，他们会要求 Claude Code 补充测试或评审他们的代码。这种自动化测试工作流为常规但重要的质量保障（QA）任务节省了大量时间。
调试与错误排查
他们使用 Claude Code 调试错误，结果好坏参半——有时它能立刻识别问题并补充相关测试，而有时它难以理解问题，但总体而言，在其奏效时能带来价值。
代码库理解与调用栈分析
他们工作流中最大的变化之一，是使用 Claude Code 快速获取相关组件和调用栈（call stack）的摘要，取代了手动阅读代码或生成大量调试输出。
Kubernetes 运维指导
他们经常向 Claude Code 询问 Kubernetes 运维问题——这些问题原本需要大量 Google 搜索，现在能立即获得配置和部署问题的答案。

开发工作流的影响
实验性方法成为可能
他们现在采用“尝试并回滚”的方法，频繁提交检查点，从而能够测试 Claude 的自主实现尝试，并在需要时回退，使开发更加具有实验性。
文档加速
Claude Code 会自动添加有用的注释，为文档工作节省了大量时间，不过他们也注意到，它有时会在不合适的位置添加注释，或使用值得商榷的代码组织方式。
提速但有局限
虽然 Claude Code 能以“相对较短的时间”实现中小型拉取请求（PR），但他们也承认，它大约只有三分之一的概率一次就成功，其余时候需要额外的指导或人工干预。
来自强化学习（RL）工程团队的重要建议
针对特定模式自定义你的 Claude.md 文件
在 Claude.md 文件中添加指令，以防止 Claude 反复犯工具调用错误，例如告诉它“运行 pytest，而不是 run；不要不必要地执行 cd——直接使用正确的路径”。这显著提高了稳定性。
采用检查点密集的工作流
在 Claude 进行更改时定期提交你的工作，这样当实验不奏效时就能轻松回滚。这能在没有风险的情况下支持更具实验性的开发方式。
先尝试一次性完成，再协作
给 Claude 一个简短的提示词，让它先尝试完整实现。如果成功（大约三分之一的概率），你就节省了大量时间；如果不成功，再切换到更具协作性、有引导的方式。

Claude Code 用于法务
法务（Legal）团队通过实验发现了 Claude Code 的潜力，同时也出于了解 Anthropic 产品体系的意愿。此外，一位团队成员还有一个个人用例，涉及为家人创建无障碍工具，以及展示该技术对非开发者的力量的工作原型。
Claude Code 的主要用例
为家庭成员定制的无障碍解决方案
团队成员为因医疗诊断而说话困难的家庭成员构建了沟通助手。仅用一个小时，他们就创建了一款使用原生语音转文字（speech-to-text）的预测性文本应用，该应用会建议回复并通过语音库（voice bank）朗读出来，解决了语言治疗师推荐的无障碍工具中存在的空白。
法务部门工作流自动化
他们创建了“电话树”（phone tree）原型系统，帮助团队成员联系到 Anthropic 内部合适的律师，展示了法务部门如何在无需传统开发资源的情况下，为常见任务构建定制工具。
团队协作工具
管理者构建了 G Suite 应用，自动生成每周团队更新，并跟踪各产品的法务评审状态，让律师能够通过简单的按钮点击快速标记需要评审的事项，而无需用电子表格来管理。
用于方案验证的快速原型开发
他们使用 Claude Code 快速构建功能原型，展示给领域专家（例如向 UCSF 专家展示无障碍工具），以便在投入更多时间之前验证想法并识别现有解决方案。

工作方式与影响
在 Claude.ai 中规划，在 Claude Code 中构建
他们采用两步流程：先在 Claude.ai 中进行头脑风暴和规划，然后再转到 Claude Code 进行实现，并要求它放慢速度、逐步工作，而不是一次性输出所有内容。
视觉优先的方法
他们经常使用截图向 Claude Code 展示他们希望界面呈现的样子，然后根据视觉反馈进行迭代，而不是用文字描述功能。
原型驱动的创新
他们强调要克服分享“傻气”或“玩具”原型的恐惧，因为这些演示能启发他人看到他们从未考虑过的可能性。
安全与合规意识
模型上下文协议（MCP）集成方面的担忧
作为产品律师，他们能立刻识别出深度 MCP 集成带来的安全隐患，并指出随着 AI 工具访问更敏感的系统，保守的安全姿态会形成壁垒。
合规工具优先级
他们主张在 AI 能力扩展的同时快速构建合规工具，认识到创新与风险管理之间的平衡。
来自法务部门的重要建议
先充分利用 Claude.ai 进行规划
在转到 Claude Code 之前，先用 Claude 的对话界面把你整个想法梳理清楚。然后让 Claude 把所有内容总结成一个逐步执行的提示词，用于实现。
增量式、可视化地工作
让 Claude Code 放慢速度、一次只实现一步，这样你就可以复制粘贴而不会被压垮。多使用截图来展示你希望界面呈现的样子。
即便不完美也要分享原型
克服隐藏“玩具”项目或未完成工作的冲动——分享原型能帮助他人看到可能性，并在通常不会互动的部门之间激发创新。
